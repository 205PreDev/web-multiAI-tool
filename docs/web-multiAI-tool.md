# web-multiAI-tool

**웹 브라우저에서 텍스트와 이미지로부터 게임 엔진에 바로 넣을 수 있는 3D 에셋을 만드는 것이 이 프로젝트의 목적입니다.** 메시와 텍스처, 리깅, 애니메이션, 효과음을 서로 다른 도구로 나눠 만들지 않고 하나의 타임라인 위에서 함께 만들어냅니다. **그리고 이것을 낯선 사용자가 URL 하나로 접속해 쓸 수 있는 공개 웹 서비스로 완성합니다.**

## 완료 조건 — 두 겹

**데모 A (코어).** 텍스트로 캐릭터를 생성하고 자동으로 리깅한 뒤 모션을 적용하고, **타격이 일어나는 프레임에 생성한 효과음을 바인딩**해서, Unity로 내보내 그대로 재생. 브라우저만으로 끊김 없이.

**데모 B (서비스).** 낯선 사용자가 공개 URL로 갤러리를 보고, 소셜 계정으로 가입해 무료 크레딧으로 에셋을 만들고, **공유 링크를 발행해 다른 기기의 브라우저에서 소리와 함께 재생되는 것을 확인.** 실제 배포 환경에서.

## 왜 이 프로젝트인가

**이 도메인에서 멀티모달은 기능 목록의 한 줄이 아니라 성립 조건입니다.** 게임 캐릭터 하나는 기하 형상과 텍스처, 스켈레톤, 모션, 효과음이 결합된 복합체이므로, 단일 모달 AI는 그중 조각 하나만 만들어낼 뿐입니다. 여러 경로에서 나온 결과가 하나의 산출물로 수렴해야 비로소 쓸 수 있는 에셋이 됩니다.

차별점은 생성 이후를 책임진다는 데 있습니다. Meshy와 Tripo, Rodin 같은 서비스는 생성 단계에서 끝나기 때문에 사용자는 결국 파일을 내려받아 Blender로 옮겨 손을 봐야 합니다. 이 프로젝트는 **생성 → 정리 → 다듬기 → 공유**를 하나의 흐름으로 잇습니다. AI의 역할도 넷입니다 — 생성기, 후처리기, 조수, 검수자.

## 반드시 지킬 것

작업 중에 놓치면 되돌리기 어려운 제약 다섯 가지입니다.

| 제약 | 내용 |
| --- | --- |
| **Hunyuan3D 2.x 사용 불가** | 라이선스 원문의 Territory 정의가 대한민국을 명시적으로 제외하고 있습니다. 상업적 이용 여부와 무관합니다. |
| **후처리 순서 고정** | 정리에서 UV, 리깅, LOD 순서를 지킵니다. 토폴로지가 정돈되지 않은 상태로 리깅에 들어가면 리깅 품질까지 함께 무너집니다. |
| **glTF의 한계를 전제로 설계** | glTF에는 오디오도 애니메이션 이벤트도 담을 수 없으므로, `extras`에 `wmt` 네임스페이스로 커스텀 스키마를 두는 것이 유일한 경로입니다. |
| **에디터 기본기는 차용** | undo와 redo, 직렬화, 다중 선택, 카메라 조작은 three.js 공식 에디터의 Command 패턴을 가져다 씁니다. 이 프로젝트의 최대 위험 구간입니다. **커맨드는 처음부터 직렬화 가능해야 합니다** — undo·조수·협업 전파의 세 소비자가 같은 커맨드를 씁니다. |
| **비용은 2중 상한** | 사용자별 크레딧과 운영자 전역 하드 캡. 모든 방어가 뚫려도 월 지출은 상한에서 멈춥니다. |

각각의 상세한 근거는 [[REQUIREMENTS]]의 7.1절, 4절 C절, 6절, 8.3절, 그리고 N-6에 있습니다.
