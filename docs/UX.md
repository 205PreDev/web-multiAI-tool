# UX 설계

무엇을 만드는지는 [[REQUIREMENTS]]에, 시스템 구조는 [[ARCHITECTURE]]에 있습니다. **이 문서는 화면의 구조와 흐름, 상태, 문구의 정본입니다.** 픽셀 수준의 시안이 아니라 구조와 규칙을 정합니다 — 시각 디테일은 구현하며 채우되, 여기 적힌 구조를 바꾸려면 이 문서를 먼저 고칩니다.

**설계의 제1원칙 — 이 도구의 사용자는 3D 전문가가 아닙니다.** Blender가 어려워서 오는 사람이 대상이므로, 전문 도구의 밀도를 흉내 내지 않습니다. 화면에 항상 보이는 것은 "지금 할 수 있는 다음 행동"이고, 전문 기능은 찾으면 있는 위치에 둡니다.

---

## 1. 정보 구조

```
공개 영역 (로그인 불필요, 경량 번들)
  /                랜딩 — 한 문장 + 대표 데모 영상/실물 + 갤러리 미리보기
  /gallery         공개 갤러리
  /v/{token}       공유 뷰어
  /login           소셜 로그인 (Google / GitHub 버튼 둘)

앱 영역 (로그인 필요, 에디터 번들)
  /studio          대시보드 — 프로젝트 목록
  /studio/{projectId}   에디터 (단일 화면 앱)
  /account         계정 — 크레딧 원장, BYOK, 삭제
```

두 영역은 [[ARCHITECTURE]] 1절의 번들 분리와 일치합니다. 공유 링크를 받은 사람은 에디터 코드를 한 바이트도 내려받지 않습니다.

## 2. 에디터 레이아웃

```
┌────────────────────────────────────────────────────────────────┐
│ 상단 바   프로젝트명 · 동기화 상태 ●   |  크레딧 잔액  |  계정   │
├──────────┬──────────────────────────────────────┬──────────────┤
│          │                                      │              │
│ 왼쪽 패널 │              뷰포트                   │  오른쪽 패널   │
│          │                                      │              │
│ 아웃라이너 │    (기즈모 · 렌더러 표시 HUD)          │  인스펙터     │
│    +     │                                      │  (트랜스폼·   │
│ 파이프라인 │                                      │   머티리얼·   │
│ 스테퍼    │                                      │   메타데이터)  │
│          ├──────────────────────────────────────┤              │
│          │  타임라인                              │  생성 패널 /  │
│          │  클립 선택 · 재생/정지 · 스크럽          │  잡 카드 /    │
│          │  이벤트 마커 트랙 + 오디오 트랙          │  조수 채팅    │
│          │                                      │  (탭 전환)    │
├──────────┴──────────────────────────────────────┴──────────────┤
│ 하단 상태 바   선택 노드 · 렌더러(WebGPU/WebGL2) · 삼각형 수      │
└────────────────────────────────────────────────────────────────┘
```

**배치 원칙.**

- **왼쪽은 "무엇이 있는가"**(아웃라이너)와 **"어디까지 왔는가"**(파이프라인 스테퍼), **오른쪽은 "선택한 것을 어떻게 바꾸는가"**(인스펙터)와 **"새로 만드는 행위"**(생성·조수)입니다.
- 타임라인은 뷰포트 아래 고정입니다. 이벤트 마커 트랙과 오디오 트랙이 같은 시간축 위에 겹쳐 보이는 것이 이 제품의 정체성이므로, 접을 수는 있어도 다른 곳으로 옮기지 않습니다.
- 오른쪽 패널의 생성·잡·조수는 탭입니다. 셋이 동시에 필요한 순간이 없고, 폭을 나누면 셋 다 좁아집니다.
- 상단 바의 **동기화 상태**(H-1↔H-8)는 세 값입니다 — `저장됨(로컬+서버)` / `로컬에만 저장됨` / `오프라인`. 공유·협업이 서버 리비전을 가리키므로 이 구분이 사용자에게 실제로 중요합니다.
- 상단 바의 **크레딧 잔액**은 상시 표시입니다(I-3). 클릭하면 원장으로 갑니다.

### 2.1 파이프라인 스테퍼

**후처리 순서 고정(C절)을 UI가 그대로 강제합니다.**

```
① 생성 → ② 정리 → ③ UV → ④ 리깅 → ⑤ 모션 → ⑥ 사운드 → ⑦ 익스포트
```

- 각 단계는 `미완 / 진행 중 / 통과 / 실패` 상태를 갖고, **앞 단계가 통과하지 않으면 다음 단계 버튼이 비활성**입니다. 비활성 사유는 툴팁이 아니라 버튼 아래 한 줄로 상시 표시합니다 — "정리 게이트를 통과해야 리깅할 수 있습니다".
- 통과한 단계는 게이트 수치를 펼쳐 볼 수 있습니다(C-1의 5게이트, C-3의 4판정). **수치를 숨기지 않는 것이 이 제품의 차별점 서사입니다** — "생성 이후를 책임진다"가 화면에서 증명되는 자리입니다.
- 실패한 단계는 N-5의 오류 문구와 재시도 버튼을 그 자리에 보여줍니다.

## 3. 핵심 흐름

### 3.1 첫 생성 (온보딩)

**별도의 온보딩 투어를 만들지 않습니다.** 빈 프로젝트의 초기 상태 자체가 온보딩입니다.

1. 새 프로젝트를 열면 뷰포트 중앙에 프롬프트 입력창 하나가 떠 있습니다 — "만들 것을 설명해보세요 · 예: 검을 든 기사". 이미지 드롭도 같은 자리에서 받습니다(B-2). 입력창 아래에 나머지 두 입구가 보조 링크로 나란히 있습니다 — **"빈 개체로 시작"**(프리미티브 추가, A-11)과 **"파일 불러오기"**(G-6). AI가 첫 행동으로 제안되지만 유일한 행동은 아닙니다.
2. 입력창 아래에 예상 크레딧이 미리 보입니다 — "약 15크레딧 · 잔액 200".
3. 생성을 누르면 입력창이 잡 카드로 바뀌고 진행률이 흐릅니다. 첫 사용자가 기다리는 이 시간에 카드 아래 한 줄로 다음 단계(정리→리깅→…)를 예고합니다.
4. 메시가 도착하면 스테퍼 ①이 통과로 바뀌고 ② 정리 버튼이 활성화됩니다. **이후는 스테퍼가 안내자입니다.**

수동·불러오기 입구로 시작한 경우에도 스테퍼는 같은 자리에서 동작합니다 — 씬에 메시가 생기는 순간 ①이 통과 상태가 되고 ② 정리부터 이어집니다. 입구가 무엇이었든 이후 경험은 같습니다(REQUIREMENTS 4절 서두).

### 3.2 생성 잡 (B-4, N-4, N-5)

- 잡은 오른쪽 패널의 **잡 카드**로 표시합니다 — 종류, 진행률, 예상/확정 크레딧, 취소 버튼.
- 페이지를 떠났다 돌아오면 `GET /jobs?active=true`로 카드가 복원됩니다. "새로고침하면 사라질까"라는 불안을 만들지 않습니다.
- 실패 카드는 오류 문구 사전(5절)의 문구 + 가능한 행동(재시도/프롬프트 수정/잔액 확인)을 보여줍니다. **제공자 오류 코드를 사용자에게 보여주지 않습니다.**

### 3.3 효과음 바인딩 (D-3 → E-5 → E-3)

대표 데모의 결정적 장면이므로 흐름을 명시합니다.

1. 타임라인에서 프레임을 고르고 이벤트 마커를 꽂습니다. 이름을 입력합니다 — `hit`.
2. 마커를 선택하면 **효과음 제안이 즉시 나타납니다** — 클립 이름 `slash` + 이벤트 이름 `hit`에서 "metal sword hitting armor, sharp impact"가 제안되고, 문장은 편집 가능합니다(E-5).
3. 생성하면 오디오 트랙의 해당 시각에 파형이 붙고, 재생하면 그 시점에 울립니다(E-4).
4. 같은 마커에서 기존 라이브러리 클립(E-2)을 고르는 경로도 나란히 둡니다.

### 3.4 공유 발행 (J-2, J-3)

1. 에셋 상세에서 "공유 링크 발행"을 누르면 **어느 버전을 공유하는지**가 명시된 확인 창이 뜹니다 — 링크는 버전을 가리키기 때문입니다.
2. 로컬에만 있는 변경이 있으면(동기화 상태가 `로컬에만 저장됨`) 먼저 저장을 유도합니다 — "공유 링크에는 서버에 저장된 버전이 보입니다".
3. 발행된 링크는 복사 버튼과 함께 표시되고, 목록에서 회수할 수 있습니다.
4. 공개 갤러리 전환은 별도 스위치이며, 전환 시 이용 조건 문구(REQUIREMENTS 7.2)를 보여줍니다.

### 3.5 공유 뷰어 (J-3)

받은 사람의 화면은 세 요소뿐입니다 — **3D 뷰(궤도 카메라) / 클립 선택 / 재생 버튼.** 재생하면 이벤트 시점에 효과음이 울립니다. 모바일 폭에서는 세로로 쌓입니다. 하단에 "이 도구로 만들었습니다" 한 줄과 갤러리 링크를 둡니다 — 이것이 서비스의 유일한 성장 경로이므로 뷰어에서 빠뜨리지 않습니다.

오디오는 브라우저 자동재생 정책 때문에 **첫 터치/클릭 이후에만** 시작합니다. 재생 버튼이 그 제스처를 겸하므로 별도 안내는 필요 없지만, 자동재생을 시도하지 않습니다.

### 3.6 협업 (K절, P2)

- 프레즌스는 상단 바의 아바타 목록으로, lock은 아웃라이너 노드 옆의 자물쇠 아이콘 + 소유자 색으로 표시합니다.
- 잠긴 노드를 편집하려 하면 차단 대신 **요청 흐름**(K-5)으로 안내합니다 — "OO님이 편집 중입니다 · 넘겨달라고 요청".
- 다른 사람의 커맨드가 재생될 때 해당 노드가 잠깐 하이라이트됩니다 — 말없이 씬이 바뀌는 경험을 만들지 않습니다.

### 3.7 드래그 앤 드롭 규칙 (A-12의 정본)

**모든 드롭은 커맨드로 실행됩니다** — undo가 따라오고, 조수와 협업 전파가 같은 경로를 씁니다. 드래그 중에는 유효한 드롭 대상이 하이라이트되고, 유효하지 않은 대상 위에서는 금지 커서를 보여줍니다. 드롭 실패는 조용히 무시하지 않고 토스트로 이유를 말합니다.

| 드래그 원천 | 드롭 대상 | 실행되는 커맨드 |
| --- | --- | --- |
| 아웃라이너 노드 | 아웃라이너의 다른 노드 | 계층 재배치(reparent). 순환 참조가 되는 대상은 비활성 표시 |
| 오디오 라이브러리 클립 | 타임라인의 이벤트 마커 | 효과음 바인딩(E-3) |
| 오디오 라이브러리 클립 | 타임라인의 빈 시각 | 마커 생성 + 바인딩을 하나의 복합 커맨드로 — undo 한 번에 함께 풀림 |
| 생성 결과·에셋 카드 | 뷰포트 | 씬에 노드 추가(드롭 지점의 바닥 평면 위치) |
| 이미지 파일 (OS) | 뷰포트·생성 패널 | 이미지→메시 생성 시작(B-2) |
| glTF/GLB 파일 (OS) | 뷰포트 | 임포트(G-6) |

## 4. 상태 설계

모든 화면 요소는 네 상태를 설계합니다 — **빈 상태 / 로딩 / 정상 / 오류.** 빈 상태는 항상 다음 행동을 제안합니다.

| 화면 | 빈 상태 문구 방향 |
| --- | --- |
| 대시보드 | "첫 프로젝트를 만들어보세요" + 생성 버튼 |
| 아웃라이너 | 3.1의 중앙 프롬프트가 대신함 (패널은 비워둠) |
| 오디오 라이브러리 | "이벤트 마커를 선택하면 효과음을 제안해드립니다" |
| 갤러리 | (운영자 시드 에셋으로 비지 않게 유지 — M9 체크리스트) |
| 크레딧 원장 | 가입 지급 행이 항상 있으므로 빈 상태 없음 |

**undo 피드백.** 커맨드 실행마다 하단에 1.5초 토스트 — "이동됨 · Ctrl+Z로 되돌리기". 조수(F-3)가 실행한 커맨드도 같은 토스트를 씁니다. 조수가 무엇을 했는지 사용자가 화면에서 확인하는 수단이 이것입니다.

## 5. 오류 문구 사전 (N-5의 정본)

`code`는 [[ARCHITECTURE]] 5절 오류 규약의 키와 1:1입니다. 문구 원칙 — **무슨 일이 있었나 한 문장 + 할 수 있는 행동 한 가지.** 기술 용어와 제공자 이름은 쓰지 않습니다.

| code | 문구 | 제시하는 행동 |
| --- | --- | --- |
| `provider_error` | 생성에 실패했습니다. 잠시 후 다시 시도해주세요. | 재시도 |
| `timeout` | 생성이 예상보다 오래 걸려 중단했습니다. | 재시도 |
| `quota_exceeded` | 지금 요청이 몰려 있습니다. 잠시 후 다시 시도해주세요. | 재시도 (Retry-After 반영) |
| `validation_failed` | 결과물이 품질 기준을 통과하지 못했습니다. | 재시도 / 다른 프리셋 제안 (C-3) |
| `download_failed` | 결과물을 가져오지 못했습니다. 크레딧은 복구됩니다. | 재시도 |
| `insufficient_credits` | 크레딧이 부족합니다. 잔액 {n} · 필요 {m} | 원장 보기 / BYOK 안내(P2) |
| `service_cap_reached` | 이번 달 서비스 생성 한도에 도달했습니다. 다음 달에 다시 열립니다. | — (정직하게 말합니다) |
| `rate_limited` | 너무 빠르게 요청하고 있습니다. {t}초 후 가능합니다. | 대기 |
| `upload_invalid` | 지원하지 않는 파일입니다. PNG/JPG 이미지 또는 GLB만 올릴 수 있습니다. | 형식 안내 |
| `conflict` (H-8 409) | 다른 기기에서 저장된 더 새로운 버전이 있습니다. | 서버 버전 받기 / 내 버전으로 저장 (7절 [[ARCHITECTURE]]) |
| `offline` | 오프라인입니다. 편집은 계속되고, 연결되면 저장됩니다. | — (차단하지 않음) |

`service_cap_reached`를 숨기거나 둘러대지 않는 것은 의도적입니다 — 무료 서비스의 한도를 정직하게 말하는 쪽이 신뢰를 만듭니다.

## 6. 반응형·접근성·시각 방향

**반응형.** 에디터는 데스크톱 전용(최소 1280px, 미만이면 안내 화면)입니다. 3D 편집을 모바일에 욱여넣는 흉내를 내지 않습니다. **갤러리·뷰어·랜딩은 모바일 우선**입니다(N-13) — 공유받는 사람의 환경은 고를 수 없습니다.

**접근성 기준선.** 전체 키보드 도달(에디터 단축키 목록 제공), 포커스 링 유지, 색만으로 상태를 구분하지 않음(스테퍼·lock 표시는 아이콘+텍스트 병행), 라이트·다크 모두에서 대비 4.5:1 이상, 뷰어의 재생 컨트롤에 aria 레이블. 뷰포트 자체의 스크린리더 대응은 약속하지 않습니다 — 지킬 수 없는 약속은 하지 않습니다.

**디자인 시스템 (N-14의 정본).** UI는 `client/ui/`의 컴포넌트 디자인 시스템 위에서 만듭니다.

- **토큰 3층.** primitive(팔레트·치수·타이포 스케일 — 의미 없음) → semantic(surface / text / accent / danger / focus 같은 역할 — 컴포넌트가 참조하는 층) → component(개별 컴포넌트가 필요할 때만). 컴포넌트에 리터럴 색·치수를 쓰지 않으며, 이 규칙은 린트로 강제합니다.
- **테마는 semantic 값 교체로만.** 에디터는 다크 기본(뷰포트가 주인공이므로 UI는 물러남), 공개 화면은 라이트·다크 모두 지원 — 두 테마가 같은 semantic 토큰의 값만 바꿔 성립해야 하고, 컴포넌트 코드에 테마 분기가 나타나면 설계 위반입니다.
- **두 번들이 같은 컴포넌트를 씁니다.** 버튼·입력·패널·카드·토스트·잡 카드가 에디터와 갤러리·뷰어에서 동일한 구현입니다. `client/ui/`는 에디터·공개 화면 어느 쪽도 import하지 않습니다([[ARCHITECTURE]] 1절).
- **컴포넌트 카탈로그.** 각 컴포넌트를 상태별(빈/로딩/정상/오류, 라이트/다크)로 격리 확인하는 카탈로그 페이지를 두고, M9 배포 전 완비합니다. 도구는 구현 시 선택합니다(Storybook 또는 Ladle).

**단축키.** three.js 에디터 관례를 따릅니다 — W/E/R 기즈모 전환, F 프레이밍, Ctrl+Z/Y, Space 재생/정지, Delete 삭제. 아웃라이너의 계층 이동은 **Alt+방향키**입니다(위아래로 순서, 좌우로 단 이동) — 드래그가 유일한 경로면 마우스를 쓸 수 없는 사용자에게 그 기능이 없는 것과 같기 때문입니다. 목록은 `?`로 열람.

**단축키는 아무 일도 일어나지 않을 때도 이유를 말합니다.** 눌러 봐야 있는지 알 수 있는 것이 단축키인데, 반응이 없으면 사용자는 그것이 "할 수 없는 조작"인지 "고장 난 기능"인지 구분하지 못합니다 — 한 줄로 이어진 계층에서는 Alt+방향키 네 방향 중 셋이 할 일이 없고, 그것이 드문 모양도 아닙니다.
