# WMT 스키마 v1 — glTF `extras` 확장

glTF에는 오디오도 애니메이션 이벤트도 담을 수 없습니다. 표준 확장에 해당 기능이 없으므로 `extras`에 자체 스키마를 두며, 이 문서가 그 계약입니다.

**이 문서는 두 구현체가 공유하는 계약입니다.** 브라우저의 익스포터(G-2)와 Unity 임포터(G-4)는 서로 다른 언어로 서로 다른 시점에 만들어지므로, 양쪽이 같은 것을 읽고 쓴다는 보장이 여기서 나옵니다. 기계 검증 단언(6절)도 이 문서를 기준으로 삼습니다.

---

## 1. 배치

| 담기는 곳 | 무엇을 |
| --- | --- |
| `asset.extras.wmt` | 오디오 클립 목록. 문서 전체에서 하나입니다. |
| `animations[i].extras.wmt` | 해당 애니메이션의 이벤트 목록 |

클립 목록을 문서 최상위에 둔 이유는 **하나의 효과음을 여러 애니메이션에서 재사용하기 위해서**입니다. 이벤트는 클립을 `id`로 참조만 하므로 같은 타격음을 여러 모션이 공유해도 파일에 한 번만 담깁니다.

`scenes[i].extras`가 아니라 `asset.extras`인 이유는 클립 목록이 씬에 종속되지 않기 때문입니다. 씬이 여럿이어도 클립 라이브러리는 하나입니다.

---

## 2. 시간의 정본은 초입니다

**이벤트의 시각은 초 단위 실수로 저장하며, 이것이 유일한 정본입니다.**

프레임 번호를 정본으로 삼지 않는 이유가 있습니다. glTF 애니메이션의 시간축이 초 단위이고, Unity의 `AnimationEvent.time` 역시 초 단위입니다. 그 사이에서 Unity는 임포트할 때 클립을 자체 프레임레이트로 다시 샘플링하는데, **프레임 번호를 정본으로 삼으면 이 재샘플링에서 어긋납니다.** 초를 정본으로 두면 재샘플링과 무관하게 값이 보존됩니다.

편집기는 사용자에게 프레임을 보여줍니다. 이때 쓴 기준 프레임레이트를 `fps`로 함께 저장하되, 이것은 **표시를 재현하기 위한 참고값**이지 시각의 근거가 아닙니다. `frame` 필드도 같은 성격이며, `time`과 어긋나면 언제나 `time`이 이깁니다.

## 3. 오디오 클립 목록 — `asset.extras.wmt`

```jsonc
{
  "asset": {
    "extras": {
      "wmt": {
        "version": 1,
        "audioClips": [
          {
            "id": "sfx_sword_impact",
            "uri": "audio/sfx_sword_impact.mp3",
            "mimeType": "audio/mpeg",
            "durationSec": 1.2,
            "source": {
              "provider": "elevenlabs",
              "prompt": "metal sword hitting armor, sharp impact",
              "generatedAt": "2026-08-08T04:12:00Z"
            }
          }
        ]
      }
    }
  }
}
```

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | :---: | --- |
| `version` | 정수 | 필수 | 스키마 버전입니다. v1은 `1`입니다. |
| `audioClips` | 배열 | 필수 | 비어 있어도 배열은 존재해야 합니다. |
| `audioClips[].id` | 문자열 | 필수 | 이벤트가 참조하는 이름이며 문서 안에서 유일해야 합니다. |
| `audioClips[].uri` | 문자열 | 필수 | GLB 바깥의 상대 경로 또는 zip 안의 경로입니다. |
| `audioClips[].mimeType` | 문자열 | 선택 | 없으면 확장자로 판단합니다. |
| `audioClips[].durationSec` | 실수 | 필수 | 임포터가 버퍼를 미리 준비하는 데 씁니다. |
| `audioClips[].source` | 객체 | 선택 | 생성 출처이며 재현을 위해 남깁니다. |
| `source.provider` | 문자열 | 선택 | 예를 들어 `elevenlabs`입니다. |
| `source.prompt` | 문자열 | 선택 | 생성에 쓴 프롬프트입니다. |
| `source.generatedAt` | 문자열 | 선택 | ISO 8601 형식입니다. |

## 4. 이벤트 목록 — `animations[i].extras.wmt`

```jsonc
{
  "animations": [
    {
      "name": "sword_slash",
      "extras": {
        "wmt": {
          "version": 1,
          "fps": 30,
          "events": [
            {
              "name": "hit",
              "time": 0.42,
              "frame": 13,
              "audio": {
                "clip": "sfx_sword_impact",
                "volume": 1.0,
                "pitch": 1.0
              }
            }
          ]
        }
      }
    }
  ]
}
```

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | :---: | --- |
| `version` | 정수 | 필수 | 3절과 같은 값이어야 합니다. |
| `fps` | 실수 | 필수 | 편집기가 프레임을 표시할 때 쓴 기준입니다. 시각의 근거는 아닙니다. |
| `events` | 배열 | 필수 | 비어 있어도 배열은 존재해야 합니다. |
| `events[].name` | 문자열 | 필수 | 이벤트 이름입니다. 예를 들어 `hit`, `footstep`입니다. 한 애니메이션 안에서 중복될 수 있습니다. |
| `events[].time` | 실수 | 필수 | **정본입니다.** 애니메이션 시작으로부터의 초이며 0 이상이어야 합니다. |
| `events[].frame` | 정수 | 선택 | `time × fps`를 반올림한 참고값입니다. `time`과 어긋나면 무시합니다. |
| `events[].audio` | 객체 | 선택 | 없으면 소리 없는 이벤트입니다. 임포터는 이 경우에도 이벤트 자체는 꽂습니다. |
| `audio.clip` | 문자열 | 필수 | `audioClips[].id`를 참조합니다. 없는 `id`를 가리키면 오류입니다. |
| `audio.volume` | 실수 | 선택 | 0 이상 1 이하이며 기본값은 `1.0`입니다. |
| `audio.pitch` | 실수 | 선택 | 재생 배속이며 기본값은 `1.0`입니다. |

## 5. 설계 원칙

**`wmt` 네임스페이스로 감쌉니다.** `extras`는 누구나 자유롭게 쓸 수 있는 자리이므로, 다른 도구가 넣은 값과 충돌하지 않으려면 이름 공간이 필요합니다.

**`version`을 담습니다.** 나중에 구조를 바꿔도 임포터가 버전을 보고 분기할 수 있어야 이미 내보낸 파일이 무용해지지 않습니다. 임포터는 모르는 버전을 만나면 조용히 실패하지 말고 사용자에게 알립니다.

**읽지 못하는 뷰어에서도 모델은 정상 표시되어야 합니다.** `extras`는 명세상 무시해도 무방한 자리입니다. 소리가 나지 않을 뿐 모델이 깨지지는 않습니다. 표준을 벗어나면서도 호환성을 잃지 않는 지점이 여기이며, 이것이 `extras`를 고른 이유입니다.

**생성 출처를 남깁니다.** 어떤 프롬프트로 만든 소리인지 기록해두면 같은 결과를 다시 얻거나 조금 바꿔 다시 만들 수 있습니다.

## 6. 기계 검증 단언

`CLAUDE.md`가 `extras` 스키마 왕복을 기계 검증 필수 구간으로 지정합니다. 아래가 그 단언 목록이며, 익스포트한 파일을 다시 파싱해 확인합니다.

| # | 단언 | 허용 오차 |
| --- | --- | --- |
| 1 | 이벤트 개수가 보존됩니다. | 없음 |
| 2 | 이벤트 이름과 순서가 보존됩니다. | 없음 |
| 3 | 이벤트 시각이 보존됩니다. | 1밀리초 |
| 4 | 모든 `audio.clip` 참조가 실제 `audioClips[].id`로 해소됩니다. | 없음 |
| 5 | 클립의 `uri`가 가리키는 파일이 실제로 동봉됩니다. | 없음 |
| 6 | `wmt` 영역을 제거해도 모델이 정상 로드됩니다. | 없음 |
| 7 | Unity 임포트 후 `AnimationEvent.time`이 원본 `time`과 일치합니다. | 1프레임 |

**7번의 허용 오차가 1프레임인 이유**는 Unity가 클립을 자체 프레임레이트로 재샘플링하기 때문입니다. 초를 정본으로 삼았으므로 오차는 재샘플링 격자에서만 발생하며, 그 크기는 최대 1프레임입니다.

### 6.1 오디오 재생 타이밍

**허용 오차는 20밀리초로 확정합니다. 판정은 귀가 아니라 자동 측정으로 하며, 3차 사용자 검증이 아니라 1차 도구 검증에 둡니다.**

**측정 대상은 오디오 하드웨어의 출력 지연이 아니라 스케줄러가 계산한 예약 시각의 오차입니다.** 하드웨어 지연은 브라우저와 장치가 정하므로 이 프로젝트가 통제할 수 없고, 판정 기준으로 삼으면 기기마다 다르게 실패합니다. 통제할 수 있고 실제로 틀리는 것은 이벤트 시각에서 예약 시각을 계산하는 부분입니다.

**측정 방법.** 타임라인 재생을 시작한 시점의 `AudioContext.currentTime`을 기준으로 잡고, 각 이벤트에 대해 스케줄러가 예약에 넘긴 값이 `기준 시각 + 이벤트 시각 ÷ 재생 배속`과 얼마나 다른지 기록합니다. **모든 이벤트에서 최대 절대 오차가 20밀리초 이하**여야 통과합니다. 실제로 소리를 낼 필요가 없으므로 CI에서 돕니다.

**함께 검사하는 것.** 타이밍보다 자주 깨지는 것은 발화 횟수입니다.

| # | 단언 |
| --- | --- |
| T1 | 이벤트 3개짜리 클립을 처음부터 끝까지 1회 재생하면 발화가 정확히 3회입니다. |
| T2 | 루프를 3회 돌면 발화가 정확히 9회이고 루프 경계에서 중복이나 누락이 없습니다. |
| T3 | 이벤트 시각을 지나 뒤로 스크럽한 뒤 다시 재생해도 이미 지난 이벤트가 다시 울리지 않습니다. |
| T4 | 재생 도중 정지하면 이미 예약됐으나 아직 울리지 않은 소리가 취소됩니다. |
| T5 | 재생 배속을 0.5와 2.0으로 두어도 최대 절대 오차가 20밀리초 이하입니다. |

**20밀리초는 문헌으로 검증한 값이 아니라 이 프로젝트가 정한 기준입니다.** 실측이 이보다 크게 나오면 값을 완화하지 말고 스케줄러를 고칩니다. 룩어헤드가 100밀리초 선행이므로 충분히 달성 가능한 범위입니다.

**설계상 주의.** 테스트가 예약 시각을 관찰할 수 있어야 하므로 **스케줄러에 예약 이력을 남기는 훅이 필요합니다.** 개발 빌드 전용 배열 하나면 되지만 6단계 착수 시점에 넣어야 나중에 뜯어고치지 않습니다.

**3차에는 타이밍을 넘기지 않습니다.** 사람에게 남는 판단은 "소리가 동작과 맞게 들리는가"가 아니라 **"그 소리가 맞는 소리인가"**, 곧 음색과 볼륨의 적절성뿐입니다.

## 7. Unity 임포터가 하는 일

glTFast 또는 UnityGLTF가 모델을 가져온 뒤, 후처리 스크립트가 `wmt` 영역을 읽어 세 가지를 수행합니다.

먼저 `audioClips`를 훑어 각 파일을 `AudioClip` 에셋으로 임포트합니다. 다음으로 애니메이션마다 기록된 이벤트를 `AnimationEvent`로 변환해 `time` 값 그대로 꽂습니다. 마지막으로 이벤트를 받아 소리를 재생하는 리시버 컴포넌트를 프리팹에 부착하면, 애니메이션을 재생하는 것만으로 정해진 시점에 효과음이 울립니다.

`audio`가 없는 이벤트도 `AnimationEvent`로 꽂습니다. 사용자가 게임 로직에서 쓸 수 있어야 하기 때문입니다.
