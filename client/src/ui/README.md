# client/src/ui — 디자인 시스템

**에디터와 공개 화면이 함께 쓰는 토큰과 컴포넌트입니다.** 요구사항은 N-14, 상세 규칙은 `docs/UX.md` 6절입니다.

## 의존 방향은 한 방향이다

```
editor/  ──┐
           ├──▶  ui/
site/    ──┘
```

**`ui/` 는 `editor/` 도 `site/` 도 import하지 않습니다.** 이 방향이 지켜져야 공유 뷰어가 에디터 코드를 끌고 들어오지 않습니다.

## 토큰 3층

`tokens.css` 에 primitive 와 semantic 이 있습니다.

- **primitive** — 의미 없는 값. `--p-gray-900`, `--p-space-4`
- **semantic** — 역할. `--c-surface-base`, `--c-text-muted`
- **component** — 개별 컴포넌트가 필요할 때만 만듭니다. 지금은 없습니다

**컴포넌트는 semantic 색만 참조합니다.** primitive 색을 직접 쓰면 테마 교체가 깨집니다. 간격·타이포(`--p-space-*`, `--p-text-*`)는 테마와 무관하므로 컴포넌트가 직접 씁니다.

## 뷰포트 안의 색

그리드·선택 외곽선·축 표시는 **UI 크롬이지만 CSS 가 아니라 three.js 머티리얼이 그립니다.** `var(--c-…)` 를 넘길 수 없으므로 `cssTokens.ts` 가 계산된 값을 꺼내 넘깁니다.

색을 TS 상수로 따로 두지 않는 이유는 하나입니다 — **같은 색이 두 곳에 적히면 테마를 바꿀 때 한쪽만 바뀝니다.** 정본은 `tokens.css` 하나입니다.

## 테마

에디터는 다크 기본, 공개 화면은 라이트·다크 모두 지원합니다. **두 테마는 semantic 토큰의 값 교체로만 갈라집니다** — 컴포넌트 코드에 테마 분기가 나타나면 설계 위반입니다.

## 리터럴 금지 — 기계가 지킵니다

컴포넌트에 리터럴 색을 쓰지 않습니다. **`designTokens.test.ts` 가 `client/src/**` 를 훑어 강제합니다.** oxlint 는 CSS 를 보지 않고 TSX 안의 문자열이 색인지도 모르므로, 이 규칙을 지키는 것은 그 테스트입니다.

함께 검사하는 것 — 참조한 토큰이 실제로 정의되어 있는가(**CSS 의 `var()` 와 TS 의 문자열 양쪽**), primitive 색을 직접 쓰지 않았는가. TS 쪽을 함께 보는 이유는 뷰포트 크롬의 토큰 이름이 거기 있기 때문입니다 — CSS 의 오타는 그 선언 하나가 조용히 사라지지만, TS 의 오타는 마젠타가 화면에 그려집니다. 둘 다 CI 가 잡아야 합니다.

**토큰이 덮는 범위는 UI 크롬입니다.** 씬 안 오브젝트의 머티리얼 색과 지오메트리 치수는 사용자가 편집하는 콘텐츠이므로 토큰의 대상이 아닙니다 — 그 값들은 씬 그래프에 저장되고 glTF로 나갑니다. 예외 파일 목록은 검사 안에 있고, 목록에 적힌 파일이 실제로 존재하는지도 함께 단언합니다(이름이 바뀌면 예외만 남고 검사는 그 파일을 그냥 훑게 됩니다).

**치수도 막습니다 — 다만 절반입니다.** N-14 원문은 "리터럴 색·치수"이고, 지금 기계가 지키는 것은 `padding` · `margin` · `gap` 뿐입니다. `--p-space-*` 눈금이 실제로 덮는 것이 그것들이기 때문입니다.

패널의 고정 폭(260px)이나 줄 높이(24px)처럼 눈금이 없는 일회성 치수는 아직 남아 있습니다. 그것까지 토큰으로 만들면 토큰이 이름 붙은 상수 창고가 되고 그것은 디자인 시스템이 아니지만, **그 판단은 아직 요구사항에 없습니다.** 여기에 예외로 적어 덮지 않고 `TODO.md` 의 남은 항목으로 세워 두었습니다.

## 대비도 기계가 지킵니다

`docs/UX.md` 6절의 "라이트·다크 모두에서 4.5:1 이상"을 `designTokens.test.ts` 가 계산합니다. `tokens.css` 를 테마별로 읽고 `var()` 사슬을 끝까지 따라가, 실제로 겹쳐 그려지는 조합의 명암비를 잽니다.

**조합 목록은 손으로 적습니다** — 어느 색이 어느 배경 위에 얹히는지는 컴포넌트 CSS 가 아는 것이라 자동으로 알아낼 수 없습니다. 새 조합을 만들 때 그 목록에 함께 적는 것이 규약입니다.
